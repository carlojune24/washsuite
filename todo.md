# WashSuite — Todo / Progress Tracker

Laundry business management app. Tauri v2 + React + TypeScript frontend,
Rust backend, SQLite (via `tauri-plugin-sql`) for local-first storage,
Bluetooth ESC/POS receipt printing (via `tauri-plugin-thermal-printer`),
targeting desktop (Windows) and Android.

Multi-branch supported (see `branches` table — every core table carries a
`branch_id`).

---

## Tech stack

- **Shell**: Tauri v2 (`src-tauri`, Rust)
- **Frontend**: React 19 + TypeScript + Vite, `react-router-dom` v7 (HashRouter — required for Tauri's custom-protocol/mobile asset loading)
- **Database**: SQLite via `@tauri-apps/plugin-sql` / `tauri-plugin-sql`. Migrations live in `src-tauri/migrations/*.sql` and run automatically on launch.
- **Printer**: `tauri-plugin-thermal-printer` (ESC/POS). On Android the `printer` field must be the paired device's Bluetooth MAC address; pairing itself is done in Android Bluetooth settings, not in-app.
- **Identifier**: `com.washsuite.app`

---

## One-time setup (run these on your Windows machine, where Tauri is installed)

- [ ] `cd washsuite && npm install`
- [ ] `npm run tauri dev` — confirm the desktop app boots and the sidebar/dashboard renders
- [ ] Install Android prerequisites (Android Studio, SDK, NDK, a configured `ANDROID_HOME`/`NDK_HOME`) per https://tauri.app/start/prerequisites/#android
- [ ] `npm run tauri android init` — generates `src-tauri/gen/android`
- [ ] Open `src-tauri/gen/android/app/src/main/AndroidManifest.xml` and add Bluetooth permissions (see "Android + printer setup" below)
- [ ] `npm run tauri android dev` — run on an emulator or a USB-connected device
- [ ] Pair your receipt printer in Android's Bluetooth settings before testing the print flow in-app

## Android + printer setup

Add to `AndroidManifest.xml` (inside `<manifest>`, above `<application>`):

```xml
<uses-permission android:name="android.permission.BLUETOOTH" android:maxSdkVersion="30" />
<uses-permission android:name="android.permission.BLUETOOTH_ADMIN" android:maxSdkVersion="30" />
<uses-permission android:name="android.permission.BLUETOOTH_CONNECT" />
<uses-permission android:name="android.permission.BLUETOOTH_SCAN" />
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" android:maxSdkVersion="30" />
```

- Printer selection: build a small "Printer Settings" screen (see Sales module below) that calls `listPairedPrinters()` from `src/lib/printer.ts` and lets the user pick + persist the printer identifier (MAC address on Android). Store it via a `settings` table (add a migration) or `@tauri-apps/plugin-store`.
- `src/lib/printer.ts` already wraps `print_thermal_printer` with a laundry receipt layout (business name, order #, line items, totals, thank-you footer). Default paper size is `Mm58` (common handheld Bluetooth printer) — change `DEFAULT_PAPER_SIZE` if your printer is 80mm.
- `tauri-plugin-thermal-printer` is a small community plugin (not an official Tauri plugin). If it becomes unmaintained, the fallback is writing a custom Kotlin Tauri mobile plugin around `DantSu/ESCPOS-ThermalPrinter-Android` for Bluetooth SPP + ESC/POS byte generation, exposed to JS the same way.

## Data model (implemented in `src-tauri/migrations/0001_init.sql`)

Tables: `branches`, `users`, `customers`, `inventory_categories`, `inventory_items`,
`inventory_movements`, `service_types`, `promos`, `orders`, `order_items`, `payments`,
`expense_categories`, `expenses`, `cashflow_entries`, `workers`, `attendance`,
`payroll_runs`, `payslips`.

Seed data included: a "Main Branch", 4 sample service types, 5 expense categories.

When the schema needs to change: **add a new migration file** (`0002_....sql`),
register it in `src-tauri/src/lib.rs` → `migrations()`. Never edit a migration
that has already shipped to a real device — SQLite migrations are one-way.
